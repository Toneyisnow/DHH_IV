# 手动航海世界地图架构设计

日期：2026-11-15。状态：架构方案，尚未实现或进行性能验收。

第二阶段更新：原东南亚渲染器上的世界分区加载已实现，当前入口、资源契约和验证边界见 `ArtSource/StreamedSeasV2/README.md`。该实现替代下文早期独立世界渲染原型；未进行硬件帧率验收。

最新修订：第一版独立世界渲染方案已撤回。用户要求控制、陆地、水面和光影完全沿用现有东南亚手动航海，仅升级地图读取方式；实施顺序为先制作七海域同风格地图，再进行地理配准与异步动态拼接。当前地图制作记录位于仓库根目录 `ArtSource/RegionalSeasV2/README.md`。下文为原始目标架构，不能将旧试验结果视为新版已验收。

## 1. 目标与基本决策

沿用一个手动航海场景、当前透视镜头、船队与航行操作。地图成为连续世界：镜头转动、缩放或船队前进时，自动补充可见海域；远景逐步简化并融入雾，过远资源自动释放。跨块不切场景、不重置船队、不重新出航。

- 经度覆盖一整圈，东西循环；纬度允许范围为南纬80°至北纬80°，南北不循环。
- 世界数据是矩形，空间拓扑相当于侧面展开的圆柱。实际渲染仍是局部平面，不构建球形地球。
- “矩形经纬网、东西边逐点直接拼接”采用等距圆柱投影（Equirectangular / Plate Carrée）。用户所称“等锥投影”与此术语有区别；本方案优先落实所描述的形状与衔接效果，不引入圆锥投影的扇形边界。[PROJ 等距圆柱说明](https://proj.org/en/stable/operations/projections/eqc.html)、[等距圆锥说明](https://proj.org/en/stable/operations/projections/eqdc.html)。
- 逻辑位置、资源分块、画面实例相互分离；资源卸载不能删除港口、探索、事件和船队的游戏状态。
- 首期保持平面航行手感，距离单位为游戏世界单位。经纬度用于地理定位；不把平面距离标称为真实海里，也不直接沿用旧UV航速数值。

## 3. 三层坐标与东西衔接

### 3.1 权威坐标

设每经纬度对应 `S` 个游戏单位，世界宽 `W=360S`、可航高度 `H=160S`。X向东、Y向北；Unity局部平面使用X/Z，Unity Y留给高度。

```text
mod(a,b) = a - floor(a/b)*b             // 对负数也返回[0,b)
x = mod((longitude + 180)*S, W)         // [0,W)
y = (latitude + 80)*S                   // [0,H]
longitude = x/S - 180
latitude  = y/S - 80
periodicDelta(a,b) = mod(b-a+W/2,W)-W/2
```

逻辑与存档使用double。`WorldPosition` 是唯一位置权威；现有 `seaX/seaY` 通过带坐标版本的适配器接入，不能与另一组可独立写入的位置长期并存。旧版Y向南，迁移需显式翻转。首期将游戏航向保持为现有东向0、顺时针正角，在世界Y向北坐标中位移为 `(cos(h), -sin(h))`，镜头、罗盘、风向、护航船统一经过方向适配器。

### 3.2 连续显示坐标

运行时另外维护连续展开的X和局部渲染原点，供插值、镜头和轨迹使用；它们是权威位置的派生表示。向东越过180°时，权威X变回0，显示X仍继续增大，因此画面没有瞬移。

同一块可在 `x+kW` 处显示，k为整数。资源键只有规范化的ChunkId，显示实例键为 `(ChunkId, k)`。两个显示副本共享资源和实体ID，不重复模拟、领取事件或创建港口。

例：船在东经179.9°，西经179.9°的岛显示在右侧0.2°处，而不是左侧359.8°处。护航船、目标标记、港口拾取和奇遇同样选择相邻展开副本。跨缝航向、到港距离、跟随距离都通过统一周期函数计算。

运动求解先在连续坐标中扫掠并累计实际路径长度，再规范化位置。不能用取模后的普通坐标差计算速度或每日里程；也不能在可能超过半圈的长时间步中用最短差值替代实际行程。保留现有不大于1/60秒的模拟子步。

### 3.3 浮动原点

Unity只接收 `float(globalUnwrappedPosition - renderOrigin)`。超出阈值时，在固定更新边界同步移动原点、地形、船、相机、粒子、尾迹和插值历史；权威位置不变。波浪、云和噪声用稳定全局相位或周期相位，不能随原点变化跳动。重置阈值通过视觉精度测试确定。

## 4. 分块数据与模块职责

建议首轮采用5°×5°基础块，形成72×32共2304个索引项；这是可调实验值，不是同时加载2304块。块内采样密度由海岸细节和实际内存决定。陆地网格、水深、碰撞可以有不同精度，但共用地理配准和海岸源数据。

```text
输入 / 船队 / 相机
       ↓
WorldCoordinates + WorldNavigation → 权威会话、里程、事件
       ↓                     ↓
CameraCoverage          NavigationCoverage
       └────── WorldStreamPlanner ──────┘
                         ↓
             ChunkRepository（异步与引用计数）
                         ↓
             WorldChunkRenderer → V2环境与镜头
```

| 模块 | 职责 |
| --- | --- |
| `WorldMapDefinition` | worldId、坐标/内容版本、投影参数、块划分、纬度限制、资源清单 |
| `WorldCoordinates` | 周期索引、连续展开、投影反投影、方向和距离；纯逻辑可独立测试 |
| `WorldStreamPlanner` | 合并视野、预测移动、护航船和目标需求，决定优先级、LOD与保留集合 |
| `WorldChunkRepository` | 异步加载、解析、资源共享、版本校验、引用计数和失败重试 |
| `WorldChunkRenderer` | 局部实例、地形接缝、LOD过渡、装饰实例化与资源解绑 |
| `WorldNavigation` | 连续扫掠、跨块海岸采样、纬度墙、海域权限，返回实际位移和阻挡原因 |
| `WorldEntityIndex` | 港口、事件的稳定ID、位置和活动实体查询；与画面生命周期解耦 |
| `WorldExplorationStore` | 按规范ChunkId保存探索增量；显示副本共享探索结果 |

每块清单记录边界、内容版本/hash、各LOD资源键、包围盒最大高度、海岸/水深数据、海域等级、港口/装饰引用及估算内存。纯海块可省略地形和装饰资源，但必须显式标为已知可航海面，不能把“文件缺失”当作海。

资源目录建议：

```text
ArtSource/WorldMap/                         原始地理数据、生成脚本、配准、接缝审查
MaritimeLegend/Assets/Resources/
  Data/WorldMap/                           索引、规则、分块导航与海域分类
  Models/Environment/WorldMap/             分块地形LOD
  Textures/Environment/WorldMap/           分块水深、地表及低清远景
  Prefabs/Environment/WorldMap/            可复用港口与装饰
```

首期资源后端沿用工程Resources，通过独立 `IWorldChunkSource` 隔离，异步请求与分帧创建分开实现。不要有一个总Prefab引用全部分块，否则会重新变成全量依赖加载。释放块实例、自建Mesh/Material/纹理及共享引用要分别记账；全局资源清理不放在每次跨块的热路径。后续如需更强的包级释放或独立更新，再替换资源后端。

## 5. 镜头驱动的加载与卸载

### 5.1 计算需求

使用相机视锥与有限可见距离体积计算覆盖块，不能只用“船所在块±1”。当前V2镜头能看见天空和海平线，上方屏幕射线不一定与海平面相交；接近水平的射线也会给出极远交点。

因此先设定雾的完全遮蔽距离和有限地形可见距离，按块的含最大山高包围盒做视锥测试，再结合海平面足迹确定需求。高山、岸边建筑和影子投射需要额外包围盒余量。镜头转向、缩放、屏幕比例或原点改变时也要重算。海面背景可覆盖至雾尽头，不依赖完整地形块。

### 5.2 四类范围

| 范围 | 加载内容 | 原则 |
| --- | --- | --- |
| 导航保障范围 | 船队当前位置、下一段扫掠路径、制动/转向余量所需精确导航 | 最高优先级，涵盖每艘护航船，独立于镜头朝向 |
| 近景范围 | 精细岸线、地形、港口和近景装饰 | 进入近景前已就绪 |
| 远景范围 | 简化地形、山体轮廓、低清纹理，减少或取消装饰 | 用雾、纹理mip与LOD过渡隐藏切换；不影响碰撞精度 |
| 预加载/保留范围 | 前方预测块、镜头周围余量及最近离开的缓存 | 尚不绘制或暂时保留，降低边缘来回抖动 |

远景用稀疏层级覆盖：需要时加载较粗父块，子块就绪后渐变替代；禁止父子地表长期重叠造成闪烁。可常驻一份严格受预算限制的全球极低清轮廓用于兜底，但不常驻全世界精细网格、导航或纹理。

预加载距离至少覆盖 `最大速度×(实测加载P95耗时+调度余量)`，并考虑镜头最大缩放与快速转向。航行方向多预取，同时保留全方向低清覆盖，应对180°转镜。阈值全部配置化。

### 5.3 更新流程

1. 从本帧镜头、船队和预测路径构建近景、远景、导航需求；X块索引取模，Y块索引不取模。y=H必须归到最后一行。
2. 合并相同资源请求；优先保障导航与当前可见空缺，再补细节、前方预取和外围缓存。
3. 后台读取/解析纯数据；Unity对象创建、绑定与上传分帧执行并设置毫秒预算。
4. 资源完整且版本匹配后原子启用；保留低清替代物直到新LOD可见，避免一帧空洞。
5. 离开更大的保留范围且冷却时间已到、没有导航/实体/显示引用的块进入释放队列；先停用实例，再释放无引用资源。
6. 统计CPU/GPU驻留、在途数据、待上传和池中内存；超预算先减装饰和远景精度，再驱逐外围缓存。为导航保障范围预留不可挪用的预算。

卸载距离大于加载距离，建议起始保留1圈块、延迟约5秒，最终以性能实测调整。对象池必须有容量上限，否则“卸载”只隐藏了对象，内存仍持续增长。

资源生命周期：`Unloaded → Queued → Loading → CPUReady → Uploading → Ready → Evicting`，失败进入可重试状态。每次请求携带会话代号/内容版本；换档、退出、传送后的过期完成回调只释放结果，不激活旧块。共享资源直到最后一个引用释放才卸载。

正常航行应在进入前完成加载。若导航数据仍未就绪，停在最后安全位置并显示“海域加载中”；不能用低清地形猜测碰撞，也不能让船穿岸。若需要整体等待，则暂时冻结航行模拟和相关日历结算，避免加载慢导致额外粮水消耗。瞬时转镜允许短暂低清远景；传送/读档先建立目的地导航与基本可见覆盖，再恢复模拟。

## 6. 跨块连续性

- 地形：所有块来自同一全球采样坐标；边界顶点和高度一致。邻块共享边缘样本与法线计算所需外圈，X最后一列向第一列取样。
- LOD：邻块级差限制为一级，使用边缘缝合或裙边；海岸附近优先缝合，不能用裙边掩盖碰撞岸线错误。
- 纹理：保留边缘外扩像素，各级mip也保持相邻采样一致，避免双线性过滤产生细线。水深和海岸距离场同样需要外圈。
- 海面：全局一致的水位、波浪时间、采样比例；原点平移和跨日期线不能重置相位。跨东西缝的噪声/天气场须周期化。
- 碰撞：分块边界只是数据边界，不是障碍；扫掠覆盖所有经过块，窄海峡不能因低LOD或缺邻块被堵住或穿透。
- 港口/事件：一个稳定实体只模拟一次，重复显示副本只负责渲染和拾取映射；卸载画面不刷新奖励。
- 探索：以规范化块坐标记录；揭开范围跨缝时同步更新两侧块，远景模糊不能误记为已探索。
- 海域：地理海域ID、近/中/远海等级、渲染块是三套独立索引。块加载不调用重新出航；实际位置跨地理区才更新海域状态。

沿用11/04设计：近/中/远海距离分类在生成阶段固定。最近海岸距离计算必须支持东西周期邻接，南北空气墙不是陆地，不参与“最近海岸”距离。海域许可与纬度墙是不同阻挡原因，不因分块加载而改变许可。

## 7. 南北纬80°空气墙

空气墙由逻辑导航强制执行，不依赖可能被卸载的Collider。所有运动入口（旗舰、护航船、脚本移动、恢复存档和调试传送）统一经过边界校验。

移动时求线段与 y=0 / y=H 的首次接触位置，到墙后去掉剩余位移的越界法向分量，允许沿东西方向继续移动，再执行相应海岸扫掠。不能只在渲染结束后把船拉回来。首期边界约束以船的导航中心为准；若后续改成船体不得越界，应统一减去船体半径。

北纬80°继续向北或南纬80°继续向南时，实际南北位移为0；斜向移动可以沿墙滑行，向内转舵立即恢复，不反弹、不传送。HUD提示“已到达北纬80°航行边界”或南侧对应文字；边界阻挡不计虚假行程或经验。

镜头可以看到边界以外的远雾和背景海面，不生成可航区域、交互目标或事件。点击越界目标应投影到边界并显示限制提示。读档非法坐标通过带日志的版本化修复处理，不能静默变成另一片海域。

## 8. 旧档和既有内容迁移

新增世界坐标版本、worldId和地图内容版本；不能仅将manualMapId改名后把0…1局部UV当全球坐标。

1. 为东南亚V2建立经纬度配准表和旧UV→新世界映射。当前手工地图若并非准确投影，需要依据港口/海岸控制点映射，不能仅套世界矩形比例。
2. 同时转换旗舰、护航船、出发泊位、事件位置与可迁移探索；旧目标和渲染原点可以重建。统一处理Y方向、航向和速度单位。
3. 保留日期、航程、金钱、货物、船况、任务和已领取事件；备份旧存档，迁移成功后原子写回新版本，重复加载不重复迁移。
4. 无法配准的旧地图保留原坐标和迁移说明，走明确的安全港恢复路径，不静默落在随机地点。探索仅迁移可靠覆盖范围，不误解锁全球。
5. 替换 `EnsureManualSea` 中固定东南亚的重置逻辑，确保读入世界档不会被再次送回东南亚。

航速按旧局部可见航行体验换算到新单位；航程阈值、跟船距离、海岸余量、视野半径与入港半径同步换算。首期不改变自动贸易经济规则，但与手动航行共用港口地理位置的入口需要适配，不能让新坐标泄漏到旧自动路线计算。

## 9. 实施顺序与验收

| 阶段 | 交付 | 核心验收 |
| --- | --- | --- |
| A 坐标与导航 | 周期坐标、连续表示、纬度墙、单位适配 | 正负越界、多圈、跨缝距离、80°边界、真实里程；无渲染依赖 |
| B 最小流式原型 | 合成地图、异步加载与引用计数、调试叠层 | 普通接缝和东西缝连续航行；注入慢加载/失败不穿岸 |
| C V2接入 | 镜头覆盖、近远LOD、海面、护航船与原点 | 快速转镜/缩放、船队分处接缝两侧、浮动原点无跳动 |
| D 世界内容 | 全球配准与分块生成、港口、海域分类、探索 | 岸线/LOD/纹理无裂缝；跨缝海域距离一致；关键航路可达 |
| E 存档与回归 | 显式迁移、读档、救援/入港及事件 | 进度不丢、事件不重复、读档不重置海域、长期内存稳定 |

必须覆盖：连续东西绕行至少3圈、接缝附近来回航行、南北边界正冲与斜冲、边界+日期线角落、最大缩放与最低俯角、180°转镜、护航船在镜头外、加载中换档/退出、跨缝保存并恢复、缩放切LOD时窄海峡碰撞、跨缝港口拾取只触发一次。

调试叠层显示：规范经纬度、展开X/原点、ChunkId与副本编号、LOD、请求队列、导航就绪范围、驻留与在途内存、主线程创建耗时。记录帧时间P95/P99、加载延迟P95、峰值内存和可见空缺次数。目标为正常航行没有可见空洞、无跨缝相机跳动，长时间绕行后内存回落到预算内；具体MB、块数和帧时间预算在目标硬件上测定，不能把未测试参数称为达标。
