# 《航海世家》人物八方向行走素材重做方案

版本：2026-11-07（计划稿，待单角色 PoC 验证）

## 1. 变更目标

原有八个预设人物概念形象继续作为设计源，不重新定义角色外观。重新制作可用于 Unity 城市角色移动的统一风格八方向行走素材。制作顺序为：八张概念图 → 各人物一张标准方向全身静图 → 八方向静图 → 每个方向的循环行走帧 → 规范化 Sprite Sheet → Unity 导入与测试。

*本次不改变既定的角色创建范围：八个预设外形，以及受控的发型、肤色、衣服颜色、饰品变化；不引入自由捏脸。* 本计划只包括设计流程与资源规格，不涉及 Unity 代码实现。

## 2. 工具调查（截至 2026-11-07）

| 工具 | 角色生成与方向 | 行走动画 | 自动化 | 用途和风险 |
|---|---|---|---|---|
| FrameRonin https://frameronin.com/ | 官网列有“完美八方向”、RPG Maker 角色生成等 | 自由序列、视频转序列帧、快速换皮 | 页面存在 API 设置/生图相关入口；**尚未核实八方向及动画的可调用公共 API 规范** | 优先用于视觉 PoC；区分普通八方向工具与 RPG Maker 限定模板 |
| PixelLab https://www.pixellab.ai/ | 基于参考图生成八方向，支持像素风和角色库 | animate-character、文本动画及骨骼动画 | 官方 REST API、SDK、MCP | 自动化主候选；输出分辨率与复杂服饰细节需要实测 |
| Ludo.ai Directional Sprites https://ludo.ai/features/directional-sprites | 同一个绑定 3D 角色渲染八方向 | walk 等动作预设 | 当前此模块**无 API/MCP/CLI** | 作为方向、比例和步态一致性的质量基线；对照现有画风 |
| MoveLab https://slothstudio.supercapybara.com/ | 单图转八方向 | 每方向 walk/run | 桌面软件、自备 OpenRouter Key | 工作流吻合，仍需验证成熟度、成本和输出质量 |
| FrameSprite https://www.framesprite.com/ | 有方向参考生成功能 | 图生动画及运动迁移 | 未明确验证完整自动化接口 | 补充动作测试；八方向功能实验性 |
| PerfectPixel Studio https://github.com/gykim80/perfectpixel-studio | 开源项目宣称八方向 | 多类动作 | 可研究源码 | 作为自建管线参考，非首先依赖的生产工具 |

**API 核实边界：** FrameRonin 首页提供“API 设置”“API 生图”等字样，不能推导为已提供公开且稳定的八方向动画 REST API。若后续需要自动化，需取得明确 endpoint、鉴权、请求配额、返回结构和商用条款，再决定是否接入。

## 3. 制作规格（PoC 初始建议，非最终锁定）

- 场景：Unity 2D/2.5D 城市行走；角色需要匹配《航海世家》既定的城市环境风格和摄像机高度，不直接照搬 RPG Maker 默认透视。
- 首个方向：建议 S（正面，面对镜头），站立全身、无遮挡、透明背景、鞋底完整可见；若现有概念图中某个三分之四方向更能表现风格，可将其作为风格参考，但仍输出正面标准静图。
- 八方向命名与排列：N、NE、E、SE、S、SW、W、NW（游戏坐标与命名映射以 Unity 定义为准）。
- 分辨率：先对 128×128 与 168×168 单帧进行 A/B 比较；服饰复杂的角色不强行缩至 64×64。PixelLab 不同模型尺寸限制不同，按调用接口核验。
- 帧数：每方向先试 4 帧和 6 帧；比较步态是否自然、有无脚部滑动。必要时尝试 8 帧。确保左右脚交替和首尾无明显跳帧。
- 播放率：先以 8–12 fps 预览，再按游戏实际移动速度调节；并非要求输出必须按此帧率生成。
- 导出：逐帧透明 PNG + 可选 Sprite Sheet（如 8 个方向 × 每方向 6 帧）；保留原始图、生成参数、提示词、修正版本和最终打包文件。
- 锚点：各方向和各帧脚底中心一致；统一基线、朝向、角色高度、透明 padding、像素采样和边缘轮廓。
- 需要重点防止：衣服左右翻转、发饰忽隐忽现、背面设计变化、手脚数量错误、裙摆异常、步长不同、头部抖动、阴影或背景残留、像素插值模糊。
- 如果是带明显非对称饰品的角色，不应直接镜像全部方向生成另一半。

## 4. 执行阶段与交付物

### P0 — 原始角色资料归档

1. 整理现有八张概念图，命名 `Character_01` ~ `Character_08`，保留原图。
2. 为每个角色定义不可变特征：发色、发型、服装轮廓、主副色、鞋子、腰带、饰品、背面应有的部件。
3. 从已有角色中挑选一名轮廓、发型和衣服较复杂的角色作为试验对象，避免只用过于简单的角色得出乐观结论。

交付：八名角色的参考图与外观约束表。

### P1 — 单方向静图 PoC

1. 将指定角色概念图输入选定生图工具，首先生成 S 方向全身像素静图。
2. 统一视角、风格、人物比例、角色在画布中的位置。
3. 比较 FrameRonin 与 PixelLab 的结果（可添加 Ludo.ai 视觉对照）。
4. 手工修复明显偏差，锁定角色“母图”，后续方向和动作都以母图为基准。

验收：服饰与概念图可辨识；画面完整、没有裁切；像素线条和配色符合城市场景。

### P2 — 八方向静图

1. 以同一母图生成八个方向，避免从已经转过方向的图再次生成导致误差累积。
2. 审核正面、背面、左右侧面、四个斜向视角的服装部件和人物身高。
3. 按统一格式导出八张透明静图，并记录哪个方向需要返工。

验收：八向人物是同一角色；头身比例、脚底基线、画面缩放一致；不对称装饰正确。

### P3 — 单角色八方向行走

1. 先选择 S 和 N 两个方向分别做 4–6 帧，检查完整前后摆臂、双脚步态及衣物摆动。
2. 再做两个斜方向，检验 AI 是否能正确表达空间方向。
3. 合格后补全剩余四方向；每个方向单独审阅静帧和循环 GIF 预览。
4. 必要时使用修帧、补间或重绘工具修正局部帧，而非全部重生成。

验收：没有明显漂移、抽搐、肢体变化，停步到行走转换不突兀，循环首尾平滑。

### P4 — Unity 验证

1. 使用透明 PNG 或 Sprite Sheet 导入 Unity，设置 Point/Nearest 采样，避免像素模糊。
2. 八方向动画各自配置并播放，验证人物转向、移动速度、脚底锚点与地面贴合。
3. 将角色放进典型城市背景中检查实际屏幕占比、遮挡、像素密度和光影搭配。
4. 与现有城市角色展示作 A/B 对比，确认达标后批准批量制作。

交付：一个试验角色的八方向 walk 动画包、GIF 预览、Unity 场景截图和问题清单。

### P5 — 扩展到八个人物

1. 固定 P1–P4 已验证的提示词、生成参数、后处理流程、画布规格和检查表。
2. 将其它七个角色按相同步骤转换，尽量批量操作，失败方向单独重试。
3. 形成八名人物的最终统一资源包，并将每次人工修复写入记录。

最终理论目标：8 名角色 × 8 个方向 × 每方向 6 帧 = 384 张行走帧（如最终选择 6 帧）。另有每角色 8 张方向静图，是否复用 idle 帧在后续决定。

## 5. 决策点

1. **工具选型**：先实际比较 FrameRonin 与 PixelLab。若 FrameRonin 的质量胜出但不提供稳定 API，可保留为手工制作工具，并用脚本完成批量清理/切图；若 PixelLab 输出可接受，优先采用 API 管线。
2. **风格锁定**：先拿一个角色在 Unity 城市场景内验收。不要因单独展示的九宫格漂亮就直接大规模投入。
3. **纹理规格**：选择像素尺寸和帧数时以 Unity 中最终显示尺寸为准，不为高分辨率增加无必要的细节。
4. **商业授权**：量产前逐个确认服务条款（生成素材的商用权、输入图隐私、API 使用约束），本次尚未作法律保证。
5. **角色换装系统**：如果将来发色、肤色、衣服颜色、饰品需独立变化，需评估预渲染多套变体、分层素材及调色板方案，不能假设一套烘焙图片自动支持全部换装组合。

## 6. 推荐的先后顺序

第一轮只做单角色：母图 → 八方向静图 → 四个方向动画（S、N、SE、NW）→ 完整八方向动画 → Unity 实测。其他七个角色在第一轮通过后才制作。
