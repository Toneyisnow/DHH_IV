# 用局部图层更新行走图：三套小样

已用 Character06 的同一组 8 方向 ×（4 行走 + 1 停止）动作做三套搭配，并接入城市。没有为每套衣服重新生成整个人物动画。

| 搭配 | 头部 | 衣服 | 饰品 |
|---|---|---|---|
| 原搭配 C1 / H5 | 原编发盘髻 | 赭黄上衣、靛蓝裙 | 原金色圈耳环、蓝色珠串 |
| 旅行搭配 C2 / H1 | 低包头巾 | 米白上衣、深褐裙 | 银色圈耳环、青色珠串 |
| 绿色搭配 C5 / H7 | 后束短编辫 | 灰绿上衣、深绿裙 | 原金色圈耳环、红色珠串 |

C/H 沿用原 catalog 的编号；C2/C5 本轮只验证上衣、裙子的主配色，原锈红肩布保持不变，不代表完成该配色的整套概念衣装。饰品只是现有珠串/耳环的颜色与材质变化，不创建或重新解释任何 A 编号。

## 最简单的分工

1. **基础动作层**保留身体、手脚、原披布和衣服细节；替换头部时使用移除了旧头部的 `Layers/body-no-head.png`，避免帽子覆盖后仍露出旧发髻。
2. **衣服颜色层**只覆盖上衣、裙子的局部遮罩，沿用原来的阴影和纹样。换颜色只需改 RGB，不再生成动作。
3. **头部替换层**为 H1 和 H7 各制作八个方向，再按 `anchors.json` 的每帧头部偏移排列成 40 格。保护原图的脸部区域；耳环不混入脸部保护遮罩，避免出现双耳环。
4. **饰品层**覆盖珠串与耳环的指定像素，最后绘制。换回原搭配时禁用所有替换层并恢复原图。

Unity 实际使用独立 SpriteRenderer 同步播放这些图层，底图与各层共用 168×168 格、脚底 pivot=(84,10)、PPU=64 和相同帧号。没有在运行时把三套完整合成图当成分层资源。`Composites/` 是离线审阅用合成图。

## 下次怎样改

### 只换衣服颜色

编辑本目录 `variants.json` 的 `top`（上衣）、`skirt`（裙子）、`beads`（珠串）RGB 数值；保留三条配方的 id 和顺序。然后从仓库根运行：

```powershell
& ./ArtSource/CharacterWalkRework_2026-11-07/WardrobeTest/Publish-Wardrobe.ps1
```

脚本重算局部图层、检查受保护像素并复制七张游戏图层到 `Assets/Resources/Sprites/Characters/Character06/WardrobeTest/`。Unity 编辑器自动重新导入；独立 exe 需要重新构建。

### 手工修一小块颜色遮罩

把 `Layers/mask-top.png`、`mask-skirt.png` 或 `mask-beads.png` 复制到本目录新建的 `MaskOverrides/`，同名保存。图集保持 840×1344；白色不透明区域表示允许修改，黑色或透明区域表示保护。编辑后重新运行发布脚本。该通道的人工遮罩会替代自动初稿，不会被下次生成覆盖。

不要直接在肤色相近的披布上使用全图颜色替换：初测发现这样会误染手臂，因此本轮关闭披布换色。新增披布配色需先画好 `mask-cape.png`，再设置 `cape` RGB。

### 换发型或头饰

`H1-generated.png`、`H7-generated.png` 是八方向局部编辑参考。生成时只要求改变头部，实际导出时只提取头部，生成图里的身体不参与合成。新的发型需要八方向图与挂点适配，不能把正面帽子复制到全部方向。

图层可直接在像素编辑器修改，需保留透明底、格子位置和脚底锚点。直接修改已导出的 `Layers/` 图层后，应仅复制对应 PNG 到游戏目录；再次运行生成脚本会从参考图重建输出。长期保留的修改应回写参考图、遮罩或挂点配置。

新长发、宽帽、长披风、武器和背包可能改变轮廓与前后遮挡，需要另做局部图层和遮挡遮罩。这轮没有验证这些复杂组合，也没有给短辫增加独立摆动动画；头部层目前随头部平移。
