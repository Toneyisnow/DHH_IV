# 非洲男性首次实测反馈

此轮用斯瓦希里海岸男性立绘生成 Character05，实际运行 Unity 分层角色，作为技能迁移测试。源图、提示词、导入代码和截图均留在项目内。它是换装验证原型，尚未获得用户对新角色动作的验收。

## 用户复查发现：首版不能当作穿戴验收标准

用户指出正面脸部仍不稳定、背向披风失配、非对称披风错误镜像，以及帽子尺寸大且浮在头顶。首轮组合枚举和缩略混搭截图未捕获这些问题。因此方法改为：正面五官母版后处理；每帧肩颈定位；不对称披风使用独立八方向源图和近远侧深度；头饰按头部尺寸/帽口佩戴深度适配并剔除帽下头发。以上经验不能被首轮“已验证”表述抵消，后续仍须用户验收。

## 实际发现与修正

- 单行五姿势的提示词仍会得到第1/3帧同臂在前。SW、W、N补画时逐一删除旧手/袖口再改前后摆；NW曾画成露出前胸的正面斜视，需要重新建立真正背面斜视。方向名字不能替代胸背轮廓检查。
- 对称裸体基础可从五个方向生成八方向，镜像后加半周期；右侧刀剑、左肩鹦鹉必须另算身体侧，不能随基础图镜像到另一侧。
- 肩部世界位置投影到正侧面时，左右肩会重叠。鹦鹉若直接放在肩中心，会盖住脸。正左/正右要增加沿前后方向的偏移，并让远肩宠物排到身体后面。检查不是只有锚点，还包括整个鸟、帽檐和脸的轮廓。
- 武器在远侧被身体遮住可能正确。装备展示应增加近侧视角，不要为了让每张图都能看见而把右腰武器搬到胸前。
- 装备源图界面显示的褐色底不代表不透明；读 alpha 后再判断。Unity 的 alphaIsTransparency 会扩散透明像素的 RGB，比较配色前后头部时只比较 alpha 和可见像素，不能因透明 RGB 不同误报。
- 披风全放在身体后面，背视图就会失踪；全放前面又盖住手。需要分方向的前后片和前景手遮罩。当前用区域遮罩验证结构，正式量产应升级为人工语义遮罩和逐帧手部深度。

## 已验证范围与边界

8色×7披风状态×4头饰状态×3武器状态×2鹦鹉状态×4工具包状态=5376组合。披风6款，头饰仅H1/H3/H5三款，挂饰六类；各槽可选无。不要写成完成8款头饰。

自动遍历全部组合、8方向和第1/3/停止帧，检查图层帧号同步；另检查移动归一化、停止帧、清空装备、配色不影响头部。所有方向五帧及代表性装备输出运行截图供人工检查。自动检查不证明全部组合都没有穿插，也不证明解剖步态正确。

当前披风下摆与挂饰采用像素级形变/挂点摆动，未逐件手绘40帧；头饰没有独立头发剔除遮罩。宽帽、兜帽、长羽毛、双手持物仍可能需要新增遮罩、姿势或基础局部变体。保持基础文件稳定不等于任意装备都无需适配。
